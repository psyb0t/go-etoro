# go-etoro

Unofficial Go clients for the eToro public API, generated from the specs eToro publishes. If you only want to use the clients from an agent, read [.agents/skills/go-etoro/SKILL.md](.agents/skills/go-etoro/SKILL.md) instead; this file is about changing the code.

## Architecture

Two generated packages, each driven by its own `gen.go`:

- REST, package `etoro` at the root: `scripts/fetch-spec.sh openapi.json` downloads eToro's OpenAPI document into `api/` → oapi-codegen with `config.yaml` → `client.gen.go`.
- WebSocket, package `etorows` in `ws/`: `scripts/fetch-spec.sh asyncapi.json` downloads the AsyncAPI document → `scripts/match-wire-types.sh` writes `api/asyncapi.wire.json`, turning number fields eToro sends as JSON strings into strings → gen-asyncapi with `ws/config.yaml` → `ws/etorows.gen.go`.

`ws/config.yaml` holds the message matchers: every push frame is an envelope of the same shape, so only `/messages/0/type` tells the message types apart.

## Stack

- Go 1.26.9.
- oapi-codegen (REST) and gen-asyncapi (WebSocket), both pinned as `tool` dependencies in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime`, `github.com/psyb0t/gen-asyncapi/asyncapirt`, `github.com/psyb0t/ctxerrors`, `github.com/psyb0t/ctxscope`.

## Layout

- `gen.go`, `config.yaml`, `client.gen.go`: the REST package.
- `ws/`: the WebSocket package and its tests.
- `scripts/`: spec download, the wire-type patch, lint and security scan scripts.
- `api/`: downloaded specs, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the specs and regenerate both packages
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- `make generate` always downloads eToro's current specs, so it can change the client even when nothing here changed. That is why CI skips the generate drift check. Review the generated diff before committing it.
- The spec portal answers non-browser user agents with 403; `scripts/fetch-spec.sh` sends a browser user agent.
- eToro's schemas declare some rate fields as numbers while the frames carry strings. Drop `match-wire-types.sh` and real frames stop decoding while the tests that build frames from the types still pass.
- eToro reuses names across component sections, so `config.yaml` turns on `resolve-type-name-collisions` and some response wrappers get a `2` suffix (`GetBalancesResponse2`).
